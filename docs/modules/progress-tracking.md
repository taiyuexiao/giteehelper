# 模块：开发进度（进度页）

> 状态：✅ 已上线（2026-09-29，含任务全景、个人成长轨迹、初始化向导）
> 最近更新：2026-09-29

## 摘要
把「分工 × PR 状态」变成任务完成度：顶层模块横排、子任务纵排成热力格，五态着色（未开始 / 设计中 / 设计定稿 / 开发中 / 已完成，**merged 代码 PR 才算完成**）。另提供个人成长轨迹（产出/节奏/协作指标）与三步初始化向导（接仓库 → 导分工 → 对身份）。入口：侧栏「进度」（全员可见）。

## 动机
团队流程是「需求文档 → 分工 → RFC 文档 PR → 评审 → 代码 PR → merged」。3D 仓库全景回答"正在发生什么"，回答不了"每个模块谁负责、做到哪一步"——本模块补这一环。

## 设计决策（均经用户拍板或确认）
1. **五态状态机**：`not_started → designing(RFC open) → designed(RFC merged) → developing(code open) → done(code merged)`。「设计定稿」是用户确认的独立中间档——RFC 先行流程里它恰好回答"RFC 都交了，代码到哪了"。
2. **PR ↔ 任务三级证据**（确定性计算，不调大模型）：ref（标题/正文 `BOSC-XXXX` 编号）> rfc（文件命中 `docs/rfcs/<slug>` → `rfc_contracts.workRefs`）> path（文件命中工作项路径模式）。每条关联保留证据类型。
3. **个人指标全员互相可见**；命名「成长轨迹」刻意避开 KPI 语感。
4. **merged 文件回填分块可续跑**（每次 ≤N 条、返回 remaining）：243 条 merged 里 220 条缺文件，部署后 CLI 跑了两轮补齐。
5. **双人模块拆分**：模块归属以分工表为准；子任务负责人识别以 PR 署名为准（本团队因共用账号暂由任务负责人承接，见下）。
6. **任务分型**：默认代码型；纯文档任务 doc merged 即完成——v1 通过 PR kind 判定，任务级手动标记待办。

## AI 补充关联
规则证据（ref/rfc/path）在真实数据上只覆盖 99/437 个 PR——大量 PR 分支里是 WS-xxxx 需求号而非 BOSC 任务号，标题也不带编号，导致看板任务状态几乎不动。补充通道：

- `ai-associate [--max=N]`（CLI）/ `POST /api/progress/ai-associate`：把任务清单 + PR 标题/分支/变更文件交给大模型，只接受有把握的匹配（≤3 个），结果落库 `pull_task_ai`；无把握的也记一行（module_id NULL）保证扫描收敛；
- 看板合并该结果为**「AI 识别」级证据**（最低优先级，规则证据永远优先），任务抽屉里的 PR 带「AI 识别」角标可审计；
- 生产实测：覆盖 97→147/437，任务 done 57→**79**、not_started 73→48；抽查（!431 向导预检→实验·开跑前检查、!426 WS-2330→被测对象登记）均正确；
- 已知代价：一条 PR 可能被标到多个任务（共享面），任务卡的 PR 列表里可人工甄别；删除 pull_task_ai 对应行即可回退。

## 时间线（纵向时间流，精确到秒）
第三个标签页，回答「这段时间谁都做了什么」：

- **形态**：纵向时间流（类审计日志），全员事件按时间倒序、按天分组，日期头吸顶；每条事件 = `HH:MM:SS` + 左轨色点（五类事件五色）+ 类型徽章 + 成员名 + 标题（可展开正文）+ Gitee 直链。刻意不做横向圆点轴——圆点读不出内容，用户明确否决；
- **两种视图**：全员流（默认）/ 点成员 chip 进入**个人时间线**（只显示该成员的行为，带一行个人摘要）；
- **过滤**：成员 chips、五类类型开关、日期范围（从/至）、关键词搜索；滚动到底自动加载更早（每次 200 条）；
- **事件流**（`src/server/timeline.ts` `buildTimeline()`）：提交 push / PR 开启 / PR 合并 / PR 关闭 / 评论 统一为 `{ts, type, actor, title, detail, url, number, sha}`；提交作者按署名邮箱解析、评论作者经别名表解析；`(number, remoteId)` 跨来源去重；
- **评论数据**（`pull_comments`）：PR 会话评论（issues 端点）+ 行内评审（pulls 端点）分块回填（`backfill-comments [--max=N]`，生产已回填 1858 条）；WebHook note 事件经 noteable_id 反查 PR 编号增量落库；
- 生产底账：3718 条事件（970 提交 / 1858 评论 / 449 开启 / 342 合并 / 99 关闭），跨度 2026-09-01 ~ 至今。

## 「完成」的口径与已知盲区（重要）
看板的 done = **该任务有已合并的代码 PR 关联**，它不等于验收完成：

- **绿卡可能是部分交付**：0062 过程类判法绿了，但引擎没实现（只有参数声明与校验，PROCESS_ASSERT 分支直接抛异常）；0064 大模型当裁判绿了，真实调用仍 BLOCKED（等行内网关协议与费用授权）。PR 状态看不见代码级/验收级事实——这些要以 RFC 验收故事和评审结论为准，抽屉里列出的关联 PR 就是审计入口；
- **反向也一样**：后端已合但页面入口未合的任务（如 0066 样题试跑）显示「开发中」而不是完成——!440 在飞、!450 已合时，页面调不通还没合的后端接口，开发中才是诚实状态；
- **半成品任务**：0070 的裁判配置半边在已合并的 !450 里、过程类半边被过程子 RFC（待撰写）阻塞——五态表达不了"完成一半"，当前保持 not_started 并在此说明，点抽屉可看到 !450 已交付的部分；
- 人工/AI 挂接的关联带角标可审计；发现漏挂直接在 `pull_task_ai` 加一行（source='manual'）。

## Bug 与问题记录

### BUG-001 汇总数丢失（2026-09-29，已解决）
- 错误行为：WHEN 看板渲染 THEN `summary.total` 恒为 0。根因：修类型时删掉了 `total` 累加。解决：分组循环里累加。验证：集成测试断言 total。

### BUG-002 SQL 参数错位（2026-09-29，已解决）
- 错误行为：WHEN 构建人员指标 THEN `column index out of range`。根因：commits 统计查询没有 `?` 却传了 projectId。解决：补上 `WHERE project_id = ?`。

### BUG-003 共享 PR 归属失真（2026-09-29，已解决，两轮）
- 错误行为：WHEN 一条 PR 关联多个人的任务 THEN「先到先得」把账全算给第一个迭代到的负责人（厉福超 16/17 任务完成却只显示 2 个 PR，全进刘成彦）；第一版修复又让所有人显示同一个协作数（漏了"本人须在关联负责人里"）。
- 期望行为：WHEN PR 关联的任务负责人唯一 THEN 计入该成员独立数；WHEN 跨多人 THEN 不重复计入任何人的独占数，单列「跨人协作 PR」。
- 不可破坏的行为：tasksDone/tasksOwned（按模块 owner 计算）SHALL CONTINUE TO 保持精确，不受共享归属影响。
- 验证方式：生产真实数据上独占/协作数分化合理（刘成彦 12 独立 + 13 协作；厉福超 2 独立 + 10 协作）。
